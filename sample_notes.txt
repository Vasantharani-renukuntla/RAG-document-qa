AI Engineering Study Notes: Retrieval-Augmented Generation (RAG) Architecture

1. Overview of Retrieval-Augmented Generation (RAG)
Retrieval-Augmented Generation (RAG) is an architectural pattern that enhances Large Language Models (LLMs) by grounding their answers on authoritative external document collections. Standard LLMs are trained on fixed datasets up to a specific cutoff date and may suffer from factual hallucination or lack domain-specific private knowledge. RAG addresses this by retrieving relevant text passages from indexed vector databases and injecting them into the prompt sent to the LLM.

2. Document Ingestion and Text Extraction
Document ingestion is the first phase of the RAG pipeline. It processes raw document formats such as PDF, TXT, and Markdown files:
- PDF Text Extraction: Using libraries like PyMuPDF (fitz), text is extracted page by page while keeping track of metadata such as page numbers and document titles. Scanned or image-only PDFs require Optical Character Recognition (OCR), while digital PDFs yield structured plain text directly.
- Text Cleanup: Ingested text is normalized to remove unnecessary control characters, fix irregular whitespace, and handle encoding variations (UTF-8, ISO-8859-1) without destroying paragraph integrity.

3. Text Chunking Strategies
Because LLMs have context window limits and embedding models perform best on focused paragraphs, documents must be split into manageable text chunks:
- Chunk Size: Typical chunk sizes range from 500 to 1000 characters. A chunk size of 800 characters provides sufficient context without diluting vector representations.
- Chunk Overlap: An overlap of 100 to 150 characters (e.g., 120 characters) between consecutive chunks ensures that sentence context across chunk boundaries is preserved.
- Boundary Respecting: Splitting on natural boundaries (paragraphs `\n\n` or sentence endings `. `) yields cleaner Semantic Chunks than arbitrary character cuts.

4. Vector Embeddings and FAISS Retrieval
Vector embeddings convert textual chunks into dense numerical vector representations in a multi-dimensional space (e.g., 384 dimensions for all-MiniLM-L6-v2):
- Sentence Transformers: Models like sentence-transformers/all-MiniLM-L6-v2 map semantically similar sentences to nearby points in vector space.
- FAISS Vector Database: Facebook AI Similarity Search (FAISS) stores vectors and enables high-speed similarity search using L2 distance or Inner Product (Cosine Similarity on normalized vectors).
- Document Filtering: FAISS indices can be queried globally or filtered by document identifiers to ensure users search only specific uploaded documents.

5. Grounded Prompt Engineering and Safety
To prevent AI hallucinations, prompt construction forces strict adherence to retrieved document contexts:
- System Instruction: The model is instructed to act as a document Q&A assistant and answer using ONLY supplied reference passages.
- Fallback Statement: If context is insufficient, the system returns: "I could not find sufficient information in the uploaded documents to answer this question."
- Prompt Injection Prevention: Uploaded document text is treated purely as data rather than instructions.

6. Evaluation & Transparency
Every answer generated by a RAG system should provide source transparency:
- Source Citation: Listing the source filename and PDF page number for each retrieved chunk used in answer generation.
- Similarity Score: Displaying the cosine similarity score for retrieved passages allows users to verify how closely the passages match their query.
